# Performance Audit Report Format Enforcer

> Validate the generated report against structural + integrity rules, fix issues in place, and export the final artifacts. Runs after report-generator.

---

Goal: Read `reports/performance_audit.md`, validate ALL checks, fix formatting in
place, then export MD + JSON + history.

## STOP-BEFORE-EXPORT CHECKS (rejection → re-run report-generator)
Reject and regenerate if ANY fail:
1. Report has the **10 numbered sections** in order (Executive Summary → Appendix).
2. Section 1 states **scope**, **profiling performed (Yes/No)**, and the **Static
   Health score with its honesty label** when `MEASUREMENT_PERFORMED=no`.
3. Section 2 Project Profile table is present (per-app rows if monorepo).
4. Section 3 scores **only the areas in scope**; out-of-scope areas are absent (not 0);
   Overall matches the weighted formula (recompute; scope weights sum to 1.00).
5. **Every finding** in Section 4 has: ID, Severity (∈ CRITICAL/HIGH/MEDIUM/LOW/INFO),
   **Confidence** (∈ HIGH/MEDIUM/LOW), Area, Location (`file:line` or explicit
   "Not found"/"N/A"), Evidence, Why it matters, Impact, Recommendation, Effort,
   **Validation**. A finding missing Confidence or Validation is INVALID.
6. Findings are ordered severity → confidence → impact.
7. **NO INVENTED METRICS:** no numeric runtime claim (LCP/INP/CLS ms, FPS, render
   count, memory MB, "%") appears unless tied to a cited profiling artifact.
   Otherwise it must read "Static analysis — …" and name a validation tool.
8. **Root-cause dedup:** no cluster of near-identical findings that should be one
   root-cause finding with an affected-locations list.
9. Section 5 Top Priorities ≤ 5, each with Impact/Effort/Expected outcome/Validation.
10. Section 8 lists validation for every static/unconfirmed claim; Section 9 avoids
    arbitrary universal budget numbers.
11. **Scope purity:** no web checks reported against a native app, or vice-versa.
12. No application code was modified (this is an audit).

## FIX-IN-PLACE FORMATTING
- Headings `## X. Section Name`. H1 title first, nothing before it.
- Severity tags `[CRITICAL]`/`[HIGH]`/`[MEDIUM]`/`[LOW]`/`[INFO]`; confidence `[HIGH|MEDIUM|LOW]`.
- Every finding cites `file:line` (or explicit "Not found"). One blank line between sections.
- No leaked generator/rubric instructions, no "SCORING HINTS", no `<system-reminder>`.
- Recommendations are specific (reject generic "use memoization"/"optimize images"
  with no what/where/why).

## EXPORTS (mandatory)
1. Markdown → `reports/performance_audit.md` (validated).
2. JSON → `reports/performance_audit.json` (schema in report-generator.md; values
   match the MD; out-of-scope `areaScores` = `null`; `measured` reflects reality).
3. History → `reports/.history/last_perf_scores.json`.
Run: `mkdir -p reports/.history`
