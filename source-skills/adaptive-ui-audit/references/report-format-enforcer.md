## STOP-BEFORE-EXPORT CHECKS (rejection → re-run report-generator)
Reject and regenerate if ANY fail:
1. Report has the **10 numbered sections** in order (Executive Summary →
   Appendix), Section 9 being the Responsive Coverage Map.
2. Section 1 states **scope**, **runtime render performed (Yes/No)**, and the
   **Adaptive-UI Health score with its honesty label** when no render was performed.
3. Section 2 Project Profile table is present (per-app rows if monorepo).
4. Section 3 scores **only the areas in scope** (web W1–W4 / desktop W1–W4+D1 /
   native N1–N4); out-of-scope areas are absent (not 0); Overall matches the
   weighted formula (recompute; scope weights sum to 1.00).
5. **Every finding** in Section 4 has: ID, Severity (∈ CRITICAL/HIGH/MEDIUM/LOW/INFO),
   **Confidence** (∈ HIGH/MEDIUM/LOW), **Evidence type** (Observed/Static), Area,
   **Affects**, Location (`file:line` OR explicit "N/A" + screenshot path if
   observed), Evidence, Why it matters, Recommendation, Effort, **Validation**. A
   finding missing Confidence or Validation is INVALID.
6. Findings are ordered severity → confidence → impact.
7. **NO-INVENTED-OBSERVATIONS:** no pixel/viewport claim (scrollWidth/clientWidth,
   "cut off", "covered by keyboard", empty-space measurement) appears as fact
   unless tied to a cited render/screenshot artifact. Otherwise it must read
   "Static analysis — render at <viewport/device/orientation> to confirm" and name
   the tool.
8. **Root-cause dedup:** no cluster of near-identical findings that should be one
   root-cause finding with an affected-locations list + count.
9. Section 5 Top Priorities ≤ 5, each with Impact/Effort/Expected outcome/Validation.
10. Section 8 lists a concrete render/device validation for every static claim;
    Section 9 Responsive Coverage Map is present.
11. **Scope purity:** no web checks reported against a native app, or vice-versa.
12. No application code was modified (this is an audit).

## FIX-IN-PLACE FORMATTING
- Headings `## X. Section Name`. H1 title first, nothing before it.
- Severity tags `[CRITICAL]`/`[HIGH]`/`[MEDIUM]`/`[LOW]`/`[INFO]`; confidence `[HIGH|MEDIUM|LOW]`; evidence type `Observed (rendered)`/`Static`.
- Every finding cites `file:line` (or explicit "N/A" + screenshot if observed). One blank line between sections.
- No leaked generator/rubric instructions, no "SCORING HINTS", no `<system-reminder>`.
- Recommendations are specific (reject generic "make it responsive"/"fix the layout"
  with no primitive/breakpoint/wrapper and no confirming viewport).
